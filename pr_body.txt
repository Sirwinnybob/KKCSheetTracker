⚡ Bolt: [performance improvement]

💡 What:
Removed the `SearchResult` data class and replaced its usage entirely with the identical `PartSearchEntry` from the search index. We also cached `query.toIntOrNull()` outside the search loop to avoid repeated string conversion and object allocation during thousands of iteration cycles.

🎯 Why:
The original code in `SearchScreen` was doing an O(N) allocation of the entire search index (`scanState.snapshot.searchIndex.map { SearchResult(...) }`), creating thousands of short-lived objects whenever the screen or index loaded. During search filtering, `r.cabNumber.toString() == query` inside the loop caused heavy string allocations per item.

📊 Impact:
Significantly reduces garbage collection overhead by eliminating thousands of object allocations on search index load and per-keystroke string allocations when matching thousands of cab numbers. Searching is visibly faster on low-end devices and uses less memory.

🔬 Measurement:
Profile memory allocations when opening the SearchScreen and typing queries. The heavy garbage collection spikes related to `SearchResult` creation and `String` allocations during the search loop will be gone.
